# Office Automation

Скрипт для macOS, который имитирует активность за компьютером: время от времени
двигает мышь, скроллит и переключается между PhpStorm и Google Chrome (нажимает
безопасные read-only хоткеи — навигация по вкладкам, Search Everywhere,
переключение методов, Page Up/Down и т.д. — никаких кликов по случайным местам
на экране), а также держит Mac от засыпания через `caffeinate`. Если вы реально
трогаете мышь/клавиатуру, автоматизация сама приостанавливается на время, чтобы
не мешать, а перед каждым действием скрипт перепроверяет, что нужное окно
(PhpStorm/Chrome) всё ещё активно — если фокус ушёл в другое место, цикл
действий сразу прерывается вместо того, чтобы слать хоткеи вслепую.

## Требования

- macOS (использует `osascript`/AppleScript и `caffeinate`, на других ОС не заработает)
- Python 3.9+
- Установленные PhpStorm и Google Chrome (иначе соответствующая часть автоматизации
  просто не будет находить, что активировать)
- Разрешение **Accessibility** для приложения, из которого запускается скрипт
  (см. ниже)

## Установка

```bash
git clone <URL-этого-репозитория>
cd office
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Разрешения macOS

Скрипт двигает мышью, отправляет нажатия клавиш и слушает клавиатуру/мышь —
для этого macOS требует явного разрешения **Accessibility**:

1. Запустите скрипт один раз любым способом (см. ниже) — macOS должна показать
   запрос на разрешение (или тихо откажет, если разрешение не выдано заранее).
2. Откройте **System Settings → Privacy & Security → Accessibility**.
3. Убедитесь, что приложение, через которое вы запускаете скрипт, включено в
   списке:
   - если запускаете через `Start Office Automation.command` (двойной клик) —
     нужно разрешение для **Terminal**;
   - если запускаете напрямую через `python3 office.py` из уже открытого
     терминала — тоже нужно разрешение для **Terminal** (или для того
     терминального приложения, которым пользуетесь — iTerm и т.п.).

Без этого разрешения мышь/клавиатура не будут реагировать на команды скрипта,
а слушатель активности выведет в лог предупреждение `This process is not
trusted!`.

Дополнительно macOS может спросить разрешение на управление System
Events/PhpStorm/Google Chrome через AppleScript (Automation) — это отдельный
запрос от Accessibility, тоже нужно разрешить, иначе `ApplicationController`
не сможет узнавать, какое окно сейчас активно, и не сможет их переключать.

## Запуск

Два равнозначных способа:

- **Двойной клик по [`Start Office Automation.command`](Start%20Office%20Automation.command)**
  — откроется Terminal и запустит скрипт через `.venv` проекта.
- **Из терминала:**
  ```bash
  source .venv/bin/activate
  python3 office.py
  ```

При старте появится окно с выбором длительности запуска: **1 час**, **2 часа**
или **без ограничений**. Дальше скрипт работает в фоне:

- `ESC` — остановить в любой момент. Остановка гарантированная: если что-то
  внутри вдруг зависнет (например, подвисший `osascript`), встроенный «сторож»
  принудительно завершит процесс максимум через ~10 секунд, в том числе
  остановив `caffeinate`.
- Реальное движение мыши/нажатие клавиш ставит автоматизацию на паузу примерно
  на 10 секунд, чтобы не мешать реальной работе.
- По истечении выбранной длительности (если не «без ограничений») скрипт
  останавливается сам.

## Логи

Всё, что раньше шло в консоль, пишется в `office.log` (рядом со скриптом,
ротация по 1 МБ, хранится 3 бэкапа). Файл в `.gitignore`, в репозиторий не
попадает.

## Настройки

Все параметры (диапазоны задержек, вероятность резкого движения мыши,
длительность паузы при реальной активности и т.д.) собраны в классе `Config`
в начале [`office.py`](office.py) — можно менять значения по умолчанию прямо
там.
